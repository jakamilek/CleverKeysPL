# Polish first-name inflection policy — 2026-09-24

## Purpose

The selected CleverKeys Polish first-name set must contain explicit singular inflected forms in the flat CKDT V2 dictionary. The current CleverKeys runtime does not derive Polish morphology from a Hunspell .aff file at prediction time.

## Scope

The authoritative name selection remains:

- 215 female names from the audited 2006–2025 official statistics;
- 215 male names from the audited 2006–2025 official statistics;
- 20 reviewed historical female names;
- 20 reviewed historical male names;
- 470 selected records in total;
- Oleksandr is excluded, leaving 469 active names.

This policy does not add names outside that selected set.

## Inflection source

For each active selected first name, the build generates singular substantive forms with Morfeusz 2 / SGJP and records:

- source name;
- gender/layer;
- grammatical case;
- generated surface form;
- Morfeusz version.

The generated forms are retained as a build artifact and verified directly against the final CKDT binary.

The build accepts the already-selected first names independently of ordinary corpus filters. This is intentional: the name selection is separately audited, and the goal of this layer is explicit inflection coverage rather than frequency discovery.

## Surface policy

The existing first-name surface policy remains authoritative:

- Jagoda, Lilia, Malina, Melisa, Róża remain lowercase ordinary-word surfaces;
- Oleksandr remains completely excluded;
- the other selected first names retain capitalized canonical surfaces.

The five lowercase common-noun exceptions are not forced through the first-name-specific capitalized layer; their ordinary-word forms remain governed by the normal Polish vocabulary/morphology pipeline.

## Case coverage

The first-name inflection layer covers singular:

- nominative (nom);
- genitive (gen);
- dative (dat);
- accusative (acc);
- instrumental (inst);
- locative (loc);
- vocative (voc).

Only forms actually generated by the Morfeusz/SGJP oracle are emitted. A name that is indeclinable or otherwise has no generated non-nominative singular form is reported explicitly rather than being filled by invented endings.

## Example

For Jakub, the CKDT acceptance gate requires at least:

Jakub, Jakuba, Jakubowi, Jakuba, Jakubem, Jakubie, Jakubie.

Duplicate lowercase keys remain prohibited by the CKDT gate.

## Provenance and licensing

Morfeusz 2 / SGJP is used as an inflectional oracle. The project does not redistribute the full SGJP database. The generated output is limited to forms needed for the already-selected first-name set, and the project retains the oracle/version provenance in CI artifacts.

Morfeusz 2 is already pinned in scripts/requirements-pl-audit.txt; the runtime version reported by the generator is recorded in build/pl-first-name-inflections-report.json.

## Regression protection

The final CKDT verification must confirm:

- every generated inflected surface for non-lowercase/non-excluded selected names is present;
- the canonical Jakub case set is present;
- the existing swipe-regression blocklist is still absent;
- the existing first-name capitalization policy is unchanged;
- CKDT remains exactly 100,000 unique lowercase keys.

This policy does not authorize automatic promotion to main.
